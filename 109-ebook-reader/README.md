# Coding Challenge #109 — Ebook Reader

An EPUB reader built in TypeScript/Node. The centrepiece is a **pure, headless
EPUB parser** that turns bytes into a typed `Book` model and knows nothing about
rendering. A small reader-logic layer (navigation, pagination, progress,
bookmarks) and a browser reader UI consume that model.

> Architectural rule (from the design): the parser library never touches the
> DOM; the UI never touches ZIP/XML internals. That boundary is what makes the
> format parsing verifiable offline against a committed fixture `.epub`.

## Layout

```
src/
  parser/   PURE, headless: ocf → container → opf (manifest/spine) → toc → Book
  reader/   PURE logic: navigator, paginator, progress, stores, html→text
  ui/       Browser reader: ReaderView + TOC + pagination + themes (DOM)
  cli.ts    Thin inspection CLI over the parser
scripts/
  build-fixture.ts   Reproducibly builds the committed test EPUBs
test/
  fixtures/          Committed .epub fixtures (regenerated by build-fixture)
  *.test.ts          Vitest suite (parser, reader logic, integration, CLI)
```

## Requirements

Node 20+ and npm on PATH.

## Install / build / test

```bash
npm install
npm run build      # tsc (strict) — compiles parser + reader + CLI to dist/
npm test           # vitest: regenerates fixtures, runs 45 tests
npm run typecheck  # tsc --noEmit over the whole tree, including the UI
```

`npm test` runs a `pretest` hook that rebuilds the fixtures from
`scripts/build-fixture.ts`, so the suite is always deterministic and offline.

## Parser API (pure)

```ts
import { parseEpub } from './src/parser/index.js';

const book = await parseEpub(bytes); // Uint8Array
book.version;          // '2.0' | '3.0' | 'unknown'
book.metadata;         // title, authors[], language, identifier, publisher, ...
book.manifest;         // Map<id, ManifestItem> (hrefs resolved + decoded)
book.spine;            // SpineItem[] reading order, linear flag
book.toc;              // unified TocNode[] from nav | ncx | synthesized
book.coverHref;        // resolved cover path (EPUB3 cover-image / EPUB2 meta)
book.getChapter(i);    // { html, basePath } — raw XHTML + base dir
book.resolveHref(from, href); // PathResolver over the archive
book.warnings;         // non-fatal parse issues
```

Fatal problems throw a typed `EpubParseError` with a `code`
(`BAD_ZIP`, `NO_CONTAINER`, `DRM_NOT_SUPPORTED`, `ZIP_SLIP`, …).

Each pipeline stage is independently usable and unit-tested: `OcfReader`,
`ContainerXml`, `OpfParser`, `TocParser`, `PathResolver`.

## Reader logic (pure, no DOM)

- `Navigator` — spine cursor; `next/prev` skip `linear="no"` items; `goToHref`.
- `Paginator` — pure page⇄offset arithmetic over injected measurements.
- `ProgressTracker` — content-anchored location + `% complete` weighted by
  chapter byte size (survives reflow).
- `BookmarkStore` / `AnnotationStore` / `SettingsStore` over a `Storage`
  interface (localStorage in the browser, in-memory fake in tests).

## Reader UI (browser)

```bash
npm run dev        # Vite dev server; open the printed URL
npm run build:ui   # production bundle into dist-ui/
```

Click **Load sample** (serves `public/sample.epub`) or **Open EPUB** to pick a
file. Features: title/author header, clickable nested TOC, reflowable CSS
multi-column pagination, next/prev (buttons + ←/→ / PgUp/PgDn keys), progress
bar, light/dark theme (`◐`), and bookmarks (`b`). Chapter XHTML is sanitized
with DOMPurify (scripts/`on*`/remote refs stripped) and images/CSS are resolved
from the archive and served as blob URLs.

## Test coverage (45 tests)

Maps to the design's test plan §7: container resolution; metadata; manifest;
spine/reading-order incl. non-linear flag and bad-idref skip+warning; TOC from
EPUB3 nav and EPUB2 NCX yielding the same unified shape; TOC synthesis when both
are absent; cover via cover-image and via `<meta name=cover>`; chapter content
markers + relative image resolution; table-driven `PathResolver` incl. zip-slip
rejection; error paths (`broken.zip`, missing container, DRM); Navigator,
ProgressTracker, Paginator, and the stores; an end-to-end `parseEpub` assertion;
and CLI stdout snapshots.

## Caveats

- Reflow/pagination uses the browser's CSS multi-column engine; the UI is
  verified manually (the *math* in `Paginator` is unit-tested headlessly).
- Later challenge steps (full-text search/library, annotations UI, dictionary
  lookup, full a11y audit) are designed-for extension points, not implemented;
  Step 1 (open/display/navigate) is complete.
- The committed fixtures are intentionally minimal, hand-built EPUBs; real-world
  EPUBs with non-well-formed XHTML are parsed leniently and sanitized, but exotic
  files may surface as `warnings`.
